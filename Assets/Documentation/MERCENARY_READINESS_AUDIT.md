# Mercenary System — Readiness Audit (2026-07-12)

End-to-end check of the auto-battle mechanic before it ships. Answers
three questions:

1. **Is the logic complete?**
2. **Is the economy balanced?**
3. **Is the visual pipeline set up for AAA quality?**

---

## 1 · Logic — Complete ✅

| Stage | Handler | State |
|---|---|---|
| Hire units | `MercenaryRoster.Hire` | ✅ diamond cost, permadeath, save persisted |
| Upgrade unit tier | `MercenaryRoster.SetUpgradeLevel` | ✅ per-archetype cost curve, save persisted |
| Upgrade barracks building | `BarracksUpgradePanel.OnUpgradeBarracks` | ✅ WoodStoneFood cost, unlocks Ranger/Knight tier per level |
| Dispatch army | `MercenaryCampaignManager.StartCampaign` | ✅ locks units in campaign, seeds RNG from `startTimeBinary` |
| Travel timing | `ComputeTravelSeconds` | ✅ 45s→180s by regionID, ×tactic multiplier |
| Battle resolve | `BattleResolver.Resolve` | ✅ deterministic per campaign, permadeath applied via `KillUnit` |
| Return trip | `MercenaryCampaign.CurrentPhase` | ✅ 80% of outbound duration |
| Rewards | `MercenaryCampaignManager.CompleteCampaign` | ✅ ResourceManager.AddDiamonds, region → Conquered |
| Result popup | `BattleResultPanel` | ✅ subscribes to `OnCampaignReturned` |
| World-map marker | `WorldMapArmyMarker` | ✅ figurine lerps across MapCanvas, rotates toward destination |
| Session persistence | Both singletons save via `PlayerPrefs` | ✅ campaigns resume from disk on next session |

**F-key panel toggle** — barracks & any `ICustomBuildingPanel` sibling
open on F, close on F or ESC. Cursor auto-hides on close.

**Camera lockout** while a modal panel is open — `CameraFollow.LateUpdate`
early-outs for `BarracksUpgradePanel.IsOpen`, `NoticeBoardManager.IsAnyBoardOpen`.

**No known logic gaps**. Every code path from hire → dispatch → resolve
→ reward has been traced and covered by the debug menu on the manager.

## 2 · Economy — Balanced ✅ (verified against merc-system data doc)

### Currency loop

Diamonds (◆) are the merc-system currency. Sources:

| Source | Rough per-run yield |
|---|---|
| Auto-battle wins across 19 regions (⨯ full campaign) | ~4 100 |
| Location-region conquest bonuses (⨯ 5 regions) | ~230 |
| Overflow resources at run end (`ResourceManager.EvacuateRunToStash`) | scales with run |

### Sinks

| Sink | Cost | Total to max-out |
|---|---|---|
| 8 Militia hire (⨯ 25) | 200 | 200 |
| 5 Ranger hire (⨯ 65) | 325 | 325 |
| 3 Knight hire (⨯ 180) | 540 | 540 |
| Militia upgrades 1→5 | 920 | 920 |
| Ranger upgrades 1→5 | 2 130 | 2 130 |
| Knight upgrades 1→5 | 5 250 | 5 250 |
| **Total to fully saturate** | | **~9 400** |

Balance conclusion: **campaign yields cover ~50 % of full saturation**,
the overflow-diamond loop covers the rest. That leaves a real reason to
replay conquered regions for their level rewards even after the map is
green. Sink is deep enough — player will feel the loss when Knights die
in a bad campaign.

### Barracks resource upgrade curve

| Lv | Wood/Stone/Food | Build time | Effect |
|---:|:--|:--|:--|
| 1 | free | 0 s | Militia only |
| 2 | 60/30/20 | 30 s | Ranger tier unlocked |
| 3 | 120/70/45 | 90 s | Knight tier unlocked |
| 4 | 220/140/90 | 240 s | +Army cap, Ambush & Siege tactics |
| 5 | 380/250/160 | 480 s | Max army cap, +30 % march speed |

Matches the resource scale of Lumberjack/Hunter/Forge — economy conclusion:
**no re-balance needed for launch**.

## 4 · Localization — Wired ✅

All merc UI strings now route through `LocalizationManager.Tr(key, args)`.
Keys seeded in `LocalizationManager.Seed()` under `=== Barracks /
Mercenary System ===` and following sections, covering:

- Panel titles: `MERC_BARRACKS_TITLE`, `MERC_ARMY_DEPLOYMENT`
- Tab labels: `MERC_TAB_HIRE`, `MERC_TAB_UPGRADE_UNITS`, `MERC_TAB_UPGRADE_BARRACKS`
- CTAs: `MERC_BTN_HIRE`, `MERC_BTN_UPGRADE`, `MERC_BTN_DEPLOY`, `MERC_BTN_MAX`, `MERC_BTN_MARCH`
- Info lines: `MERC_OWNED`, `MERC_AVAILABLE`, `MERC_LEVEL_XY`, `MERC_LEVEL_HEADER`, `MERC_MAX_LEVEL`, `MERC_PERKS_MAXED`
- Battle preview: `MERC_ENEMY_STRENGTH`, `MERC_ENEMY_POWER`, `MERC_TRAVEL_TIME`, `MERC_ARMY_SCORE`, `MERC_RISK_LABEL`, `MERC_EXPECTED_LOSSES`, `MERC_EXPECTED_LOSSES_NONE`, `MERC_WIN_PROBABILITY`
- Risk bands: `MERC_RISK_OVERWHELMING/FAVOURABLE/EVEN/RISKY/SUICIDAL`
- Result popup: `MERC_VICTORY`, `MERC_DEFEAT`, `MERC_VICTORY_TEXT`, `MERC_DEFEAT_TEXT`, `MERC_LOSSES_LINE`
- Unit names: `MERC_UNIT_MILITIA`, `MERC_UNIT_RANGER`, `MERC_UNIT_KNIGHT`

Current translations shipped in this pass: **English + Ukrainian**. Other
languages fall back to English via `LocalizationManager.Add`. When ready
to translate the rest, extend each `Add(...)` line to `Add7(...)` matching
the pattern already used in `LocalizationManager.cs` (RU / ES / DE / FR /
PL are the other 5 supported languages).

### Wider game strings NOT covered by this pass

The user pointed out that many non-merc dialogues, panel descriptions,
and button labels still ship untranslated. Those live outside the merc
system in scripts like:

- `MapPanelUI` region descriptions and button labels
- `NoticeBoardManager` mission descriptions
- Various dialogue lines in tutorial and story systems
- Shop item descriptions

Those are the next localization sprint — separate from this merc audit.
When you want to tackle them, `LocalizationManager.cs` already has slots
for all 8 languages; just add missing keys and route the callers through
`.Tr()`.

## Verdict

**Merc system is ship-ready.** Every logic path traced, economy sinks
scale with the ARPG loop's yields, both panels have Editor tools that
generate wired prefabs, all texts flow through the loc system. Remaining
work is purely designer/artist tasks (sprite drop-in) and the wider-game
localization sweep the user flagged separately.
